Coach: Please share one model function that accepts a parameter and uses it in an SQL query.

Martin:
const getCategoryDetails = async (categoryId) => {
    const query = `
        SELECT category_id, name 
        FROM public.category 
        WHERE category_id = $1;
    `;
    const result = await db.query(query, [categoryId]);
    return result.rows.length > 0 ? result.rows[0] : null;
};

Coach: What does this model function do, and why do you use $1 instead of putting categoryId directly into the string?

Martin: It retrieves a single category from the database using its ID. Using $1 parameterizes the query, which prevents SQL injection attacks by sanitizing the user input.

    try {
        const categoryId = parseInt(req.params.id, 10);

Coach: How does req.params.id get its value, and what happens if no category is found?

Topic 4: Error Handling

Coach: Please share your strategy and code snippet for handling errors like 404 or 500 status pages.

Martin:
// 404 Handler - Catch unmatched routes
app.use((req, res, next) => {
    const err = new Error('Page Not Found');
    err.status = 404;
    next(err);
});

// Global Error Handler (500 / custom error status)
app.use((err, req, res, next) => {
    const status = err.status || 500;
    res.status(status).render('errors/error', {
        title: status === 404 ? '404 - Page Not Found' : '500 - Server Error',
        message: err.message || 'An unexpected error occurred.',
        status
    });
});

Coach: How does Express know this middleware is designed specifically for handling errors?

Martin: Express recognizes error middleware because the function signature takes four parameters: (err, req, res, next). Whenever next(err) is called, Express skips normal middleware and jumps straight to this error handler.
